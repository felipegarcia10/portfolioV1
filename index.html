BUILD // 01 Shipped

Rootbound

A narrative puzzle-platformer about a forest that remembers what you do to it.

Role
Solo developer & designer
Stack
Godot 4, GDScript, Aseprite
Platform
Windows, macOS, Web (itch.io)
Timeline
7 months, 2025
Play on itch.io View source on GitHub

The problem

Puzzle-platformers usually treat the environment as static scenery you solve around. I wanted the environment itself to be the puzzle's memory — a level that visibly changes shape based on the player's past choices, without ever showing a menu, a meter, or a save-state indicator.

The decision

I built a lightweight "growth graph" underneath the tilemap: every root the player grows is a node with a timestamp and a parent. Instead of scripting bespoke triggers per room, rooms just query the graph and render themselves accordingly. That one decision let 14 hand-built rooms react to player history with about 400 lines of logic, not 4,000.

The result

Rootbound shipped to itch.io and crossed 3,200 downloads in its first month, with a 91% positive rating across 140+ ratings. Two separate outlets covered it in "puzzle games with quiet storytelling" round-ups. Replace this paragraph with your own real numbers once you have them.

BUILD // 02 Shipped

Driftwatch

A real-time marine weather dashboard for small-boat sailors, built to work on a phone in direct sun.

Role
Full-stack developer
Stack
React, Node.js, WebSockets, NOAA buoy API
Platform
Web (responsive), installable PWA
Timeline
3 months, 2024
View live site View source on GitHub

The problem

Existing marine forecast sites were built for desktop, buried the numbers sailors actually need (gust speed, swell period) under decorative charts, and were unreadable outdoors. A local sailing club asked for something that worked one-handed, on a cracked phone screen, in full sun.

The decision

I stripped the UI to five numbers and one directional compass, streamed updates over a WebSocket instead of polling, and built a genuine high-contrast mode — not just a dark theme — tuned against a phone held outside at noon. The whole interaction model fits on one screen with no scrolling.

The result

Adopted by two sailing clubs as their default pre-launch check. Around 400 weekly active users during sailing season, with sub-second update latency from buoy to screen. Swap in your real usage numbers and any testimonials once you have them.

BUILD // 03 In development

Nightshade Arcade

A browser-based, four-player local-object party game — think a haunted board game night, playable from any laptop.

Role
Gameplay programmer & network architecture
Stack
Phaser 3, TypeScript, Socket.IO, Redis
Platform
Web (desktop & tablet)
Timeline
Ongoing since early 2026
Play the demo on itch.io View source on GitHub

The problem

Local multiplayer party games usually require everyone to own the same console. I wanted the same couch-energy with zero install: one host opens a link, everyone else scans a code with whatever device is in their pocket.

The decision

Phones act as controllers only — no rendering, no state — while the host browser tab owns the authoritative game state and renders the shared screen. That split keeps phone-side code trivial and puts all the interesting netcode problems (reconnects, latency compensation, out-of-order input) in one place I can actually test.

The result

Currently in closed playtesting with three local game nights and one online playtest group. Public demo and full release timeline coming soon — update this section as milestones land.
